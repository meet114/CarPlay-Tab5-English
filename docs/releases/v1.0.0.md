# CarPlay-Tab5 v1.0.0

> This document records the v1.0.0 first-release snapshot. After that release, current main added experimental authentication materials; see [Software Authentication Setup](../software-authentication-setup.md) for how to obtain them. The original tag and release attachments are unchanged.

Date: 2026-11-14 (Australia/Sydney). First versioned release. Target: M5Stack Tab5 / ESP32-P4 v1.x; wired CarPlay; not an Apple-certified product.

## Features

- USB enumeration, NCM, USBMUX, Lockdown pairing/TLS, iAP2, and AirPlay sessions.
- 890×240 software decode targeting 16 fps; touch; music; navigation-prompt mix; microphone and Siri.
- Persistent volume/brightness settings; waiting-page Clear pairing with second confirmation and exit protection.
- Navigation stream-ID recycle fix; USB stopped-error channel completion-event fix; TX/RX watchdogs; port power recovery; and a 15-second independent task progress guard.
- SD logging and crash records; charge control.
- Merged remote PCM starvation recovery, authenticated audio-packet regression, and Required CI; kept the existing dual-path audio and persistent settings.

## Cleanup in this release

- Firmware version is centralized in `version.txt` and written into the ESP-IDF app description, boot log, and waiting page.
- Removed offline demo, boot audio self-test, one-shot clear-pairing maintenance firmware entry points, and simulated-display branches.
- Synthetic H.264 test assets no longer enter the application image; host decode regression assets are retained.
- Deleted nine temporary `tools/perf/add_*.py` source-rewrite scripts; kept offline analysis and CRC replay tools.
- Kept USB, protocol, pairing, audio, decode, crypto, and UI regressions; updated host UI stubs and the unified test entry point.
- Tidied the CMake source list, bilingual README, authentication notes, and release scripts. Kept validated runtime parameters; did not opportunistically retune decode strategy or chase the iPhone 17 phone-switch issue.

## Firmware and release scope

| Build | Auth identity | Can enter CarPlay directly | Intended use |
|---|---|---|---|
| `local-auth` | Embeds the local experimental identity | Usable on verified phones; Trust / Allow is still required | Keep local; do not upload publicly |
| `no-auth` | No identity included | No; stops at missing authentication | Development and source-build verification |

Source in the public repository does not include `secrets/mfi`. A public release does not automatically authorize redistributing authentication materials. Auth-bearing firmware can yield the private key; source license and authentication-material rights are separate. Details: [Software Authentication Setup](../software-authentication-setup.md).

Each build produces:

- `carplay-tab5-v1.0.0-<build>-app.bin`: application upgrade, flash address **0x10000**, preserves NVS.
- `carplay-tab5-v1.0.0-<build>-full.bin`: full init for new devices, flash address **0x0**. Overwrites bootloader/partition table and clears old pairing and settings within the covered range.
- `manifest.json`: version, build options, Git state at build time, chip target, image size, and SHA-256.
- `SHA256SUMS`, full build config, flash instructions, and licenses.

The release partition table is 24 KiB NVS + 4 MiB factory. Deployed boards previously used an 8 MiB factory; upgrading this application does not require changing the existing partition table. Only new-device initialization with this release's `-full.bin` applies the release partition table.

## Build and regression

```sh
source <esp-idf-v5.5.3>/export.sh
python3 scripts/fetch_openh264.py
python scripts/release.py --auth local
python scripts/release.py --auth none
./scripts/test_host.sh
./scripts/test_ui.sh
./scripts/test_crypto.sh
./scripts/test_decoder.sh build-release-local-auth
```

Release builds use separate directories and explicit authentication switches so they do not inherit card-reader firmware, maintenance mode, or a developer's private sdkconfig. OpenH264 download is pinned to commit `652bdb7719f30b52b08e506645a7322ff1b2cc6f` with every Git blob checksummed; ESP-IDF is pinned to v5.5.3, with components locked in `dependencies.lock`.

## Existing on-device evidence and acceptance boundaries

- iPhone 12 Pro Max / iOS 16.1.1: clear, re-trust, CarPlay video, and music already passed. Clear-button recheck: ~4 minutes continuous casting, 2,824 frames with no decode/output errors; music 31,017 packets with no bad packets or sample loss/reorder; manual unplug returned to the waiting page.
- Navigation fix baseline: ~1 hour 42 minutes continuous, 85 navigation prompts with no rejects; another hour sampled 100 navigation stream open/close cycles with no rejects, but one non-manual USB disconnect and recovery occurred—cannot claim zero dropouts.
- USB recovery baseline: controlled injection of stopped TX channel error, lost TX completion, and lost RX completion all recovered video; task-stall protection was verified on device.
- The soak / fault-injection results above come from the same-function baseline before the release cleanup. Final post-cleanup v1.0.0 build and device acceptance are recorded separately in the [execution log](../execution-log.md); older logs do not substitute for accepting the new image.

## Known issues

1. **Switching phones may require rebooting Tab5.** iPhone 17 Pro / iOS 26.5 did not connect after Clear; only after rebooting Tab5 did the user confirm success. No failure log was captured; root cause is undetermined. This release keeps that known issue.
2. **Recommended phone-switch steps:** unplug the old phone → Clear pairing → confirm → reboot Tab5 → plug in the unlocked new phone → confirm Trust / Allow CarPlay. Current NVS capacity is limited; long-term coexistence of multiple phones is not guaranteed.
3. USB cable/power quality and real sporadic errors can still cause disconnects; existing automatic recovery does not guarantee never dropping.
4. Low-resolution software decode limits clarity/frame rate; frame rate may drop during music; occasional video OOM rejects are not fully eliminated.
5. I2S stream-open disable log noise and this board's cold-boot other_watchdog behavior still exist.
6. Full phone call flow, echo cancellation, battery life, and low-battery protection are not fully verified; there is no wireless CarPlay.
7. Flash/NVS are not encrypted; private keys and pairing material must not be uploaded as ordinary release attachments; local logs may also contain phone screen/identity information.
